本仓库为纯前端 React + Vite 应用，未引入统一错误框架（如 Sentry、自定义 Error 类或全局中间件），而是采用「静默降级 + 日志记录」的轻量策略，围绕三类场景组织：

1. 网络/数据库层（Supabase）
   - src/lib/db/errorBankApi.ts、progressApi.ts、gemApi.ts、userApi.ts 等 API 函数在 Supabase 调用返回 { error } 时直接 throw error，将异常上抛给调用方。
   - 上层通过 useAppInit.ts 的 backgroundSync() 和 migrateLocalStorageToSupabase() 包裹 try/catch，捕获后仅 console.warn / console.error，不中断渲染；同时通过 registerVisibilitySync() 在页面隐藏时由 SyncManager.syncAfterSession() 重试。
   - syncManager.ts 内部对批量 upsert 使用 Promise.all(tasks) 并行执行，任一失败仅打印 [SyncManager] Sync failed:，本地 pending 数据保留到下次触发。

2. 本地存储层（localStorage）
   - src/lib/storage.ts 封装 getStorageItem / setStorageItem，对 JSON.parse / setItem 分别 try/catch，解析失败回退默认值，写入失败静默忽略，保证 UI 始终可用。

3. 浏览器能力层（Web Audio / SpeechSynthesis）
   - src/lib/sounds.ts 对 AudioContext、new Audio().play()、speechSynthesis.speak 等可能因用户未交互或权限不足而拒绝调用的 API，全部用 try/catch 包裹并静默降级（例如音频播放失败则回退到 TTS）。

约定与约束
- 禁止 throw new Error(...) 抛出业务语义错误对象，所有可恢复异常均以 console 日志 + 降级路径表达。
- 无全局错误边界组件（React Error Boundary）或路由级 catch-all，错误不会弹窗阻断用户流程。
- 无 panic/recover 概念（JS 环境），也未定义统一的错误码枚举。
- 迁移逻辑以幂等标记 MIGRATION_KEY 保护，Supabase 不可达时跳过而非报错退出。

该模式适合儿童学习类单页应用：优先保证首屏即时可用，后台异步容错，避免任何错误导致白屏或阻塞交互。
