本仓库为儿童学习类 React 单页应用，未引入统一错误框架或自定义 Error 类型，而是采用「分层静默 + 关键路径透传」的轻量策略：

1. I/O 层（Supabase API）：src/lib/db/*.ts 中每个异步函数在 Supabase 返回 error 时直接 throw error，不做包装，将原始错误对象向调用方冒泡。
2. 同步协调层：src/lib/db/syncManager.ts 的 SyncManager 是唯一的 try/catch 集中点，捕获所有批量同步失败后仅 console.error 记录日志并忽略异常，保证本地 localStorage 数据不丢失、下次页面可见性变化时自动重试；同时通过 pendingSync 标志实现幂等重入保护。
3. 初始化层：src/hooks/useAppInit.ts 的 backgroundSync / migrateLocalStorageToSupabase 使用 try/catch 包裹整个迁移与拉取流程，失败时 console.warn 降级到纯本地模式，不影响首屏渲染。
4. UI 交互层（音频）：src/lib/sounds.ts 对 Web Audio API 和 Audio.play() 全部用 try/catch + .catch(() => {}) 包裹，任何浏览器兼容性或用户未交互导致的播放失败均被静吞，必要时回退到 SpeechSynthesis 兜底朗读。

设计决策：
- 无全局错误边界（React Error Boundary）、无 Sentry/LogRocket 等上报服务，错误以 console.warn/error 输出到开发者控制台。
- 不定义业务错误码或自定义 Error 子类，上层组件也不消费具体错误信息，用户体验上表现为「网络不可用时功能降级而非报错弹窗」。
- 所有持久化操作遵循「先写 localStorage，再后台异步同步 DB」模型，DB 失败不会阻塞主流程。

开发者应遵循的规则：
- 新增数据库 API 函数：复用 { data, error } = await supabase... 解构并在 error 存在时 throw error，由调用方决定如何处理。
- 涉及用户可感知的副作用（如音频播放）：一律用 try/catch 包裹并静默处理，确保 UI 不因资源加载失败而崩溃。
- 需要聚合多个 I/O 操作的场景：参考 syncManager.syncAfterSession 的模式，用 Promise.all 并行执行并在外层 try/catch 统一降级。
