本仓库是一个面向儿童的 React 学习应用，错误处理整体遵循「用户体验优先、静默降级、本地数据兜底」的设计哲学，未引入统一错误类型或全局中间件，而是按场景分散处理。

## 1. 系统/方法概览
- 无统一错误类型：没有定义自定义 Error 子类或错误码枚举，网络层直接抛出 Supabase SDK 返回的 error 对象。
- 静默降级（Silent Fallback）：音频播放等用户可忽略的错误一律 try/catch 后空处理或回退到备选方案（如浏览器语音合成），不中断主流程。
- 本地优先（Local-first）：所有持久化状态通过 Zustand + persist 自动落盘，Supabase 同步失败时仅 console.warn，不影响渲染。
- 异步同步失败容忍：初始化阶段使用 Promise.all 并行拉取多表数据，任一失败不会阻断其他数据的 hydrate。

## 2. 关键文件与职责
- src/hooks/useAppInit.ts：应用启动入口，负责迁移、后台同步、重置；集中捕获 Supabase 不可达并降级为纯本地模式
- src/lib/db/errorBankApi.ts：错题本 API，对 Supabase 调用结果做简单 if (error) throw error 透传
- src/store/useErrorBankStore.ts：错题本状态管理，记录错误/正确次数并计算复习间隔，异常由上层捕获
- src/lib/sounds.ts：音频模块，大量 try/catch + .catch(() => {}) 实现播放失败的静默降级与英文语音兜底
- src/lib/db/syncManager.ts：后台同步队列，失败时 console.error 但不抛错，保证 UI 持续可用

## 3. 架构与约定
- API 层：每个 fetch* / upsert* 函数在检测到 error 字段时直接 throw error，调用方自行决定 catch 行为。
- Hook 层：useAppInit 作为唯一协调者，用 try/catch 包裹整个迁移+hydrate 流程，失败仅 console.warn 并继续执行 registerVisibilitySync()。
- Store 层：Zustand store 内部不抛错，只更新状态；持久化由 zustand/middleware/persist 自动处理，解析失败会触发其内置恢复逻辑。
- UI 层：组件中几乎不出现 try/catch，依赖 Store 和 Hook 提供的安全接口。

## 4. 开发者应遵循的规则
1. 不要吞掉业务错误：API 层的 throw error 是向上冒泡的唯一通道，不要在 errorBankApi.ts 这类薄封装里 catch 掉。
2. 用户可忽略的错误必须静默：音频播放、动画等体验型操作一律 try/catch 或 .catch(resolve)，禁止弹出 alert 或中断流程。
3. 网络失败永远有本地兜底：新增任何云端数据读写时，确保 localStorage/Zustand persist 已覆盖该字段，使离线也能运行。
4. 日志带前缀：现有代码使用 [AppInit]、[Migration]、[SyncManager] 等前缀，新模块也应保持一致以便过滤。
5. 避免在 Store 内抛错：Store 只负责状态变更，异常应由调用方（Hook/页面）捕获并展示友好提示。
