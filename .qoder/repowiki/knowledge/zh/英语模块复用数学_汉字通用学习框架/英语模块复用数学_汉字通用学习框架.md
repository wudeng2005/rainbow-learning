# 英语模块复用数学/汉字通用学习框架

_来源：f55d7d3 → 7dbed80 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
新增英语学科需与现有中文、数学模块保持一致的学习体验，避免为每个学科重复实现进度管理、错题本、宝石奖励等通用能力。

## 决策驱动
- 开发效率（复用已有 store/page 模板）
- 用户体验一致性（统一交互态 idle/correct/wrong/disabled/reveal）
- 维护成本最小化

## 备选方案
- **直接复刻 useMathLearningStore + MathLearnPage 模式** — 优点：零额外架构设计，1:1 复制即可上线；错题本、宝石、每日出题逻辑全部复用；缺点：英语特有需求（如四种题型 Renderer 分派）需在通用框架上扩展
- **为英语新建独立 Store/Page 体系** _（已否决）_ — 优点：完全隔离，不受其他学科影响；缺点：重复实现 dailyProgress / submitAnswer / nextQuestion 等相同逻辑；后续三科各自维护成本高

## 决策
以 `useMathLearningStore.ts` 为蓝本创建 `useEnglishLearningStore.ts`（persist key 改为 `rainbow-english-progress`），页面层新建 `EnglishLearnPage.tsx` 并复用 `OptionCard` 交互态，通过 `question.type` 在内部分派到四个 Renderer，从而复用通用学习框架。

## 影响
英语与中文/数学共享同一套进度持久化、错题本、宝石发放机制，新增学科只需扩展类型定义和 Renderer；但通用框架需支持按 subject 区分 ID 前缀（e_ vs m_ vs c_）。
