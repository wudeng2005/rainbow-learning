## 错误处理系统概述

彩虹学堂应用采用**本地优先（Local-First）**架构，错误处理围绕两个核心原则：**用户体验不中断**和**数据持久化保障**。应用没有统一的错误类型定义或全局错误中间件，而是采用分散式的、场景化的错误处理模式。

## 主要错误处理模式

### 1. localStorage 操作容错
在 `src/lib/storage.ts` 中，所有 localStorage 操作都包裹在 try-catch 中，失败时返回默认值或静默忽略：
- `getStorageItem`: 解析失败时返回默认值
- `setStorageItem`: 写入失败时静默处理，不影响主流程

### 2. Supabase 网络请求错误传播
数据库 API 层（`src/lib/db/*.ts`）采用**错误向上抛出**策略：
- 所有 Supabase 调用失败时直接 `throw error`
- 由上层调用者决定如何处理（同步、重试或降级）

### 3. 初始化阶段容错降级
`useAppInit.ts` 中的后台同步采用**优雅降级**：
- Supabase 连接失败时记录警告日志并继续使用本地数据
- 迁移失败时不阻塞应用启动，下次重试
- 使用 `console.warn` 而非 `console.error` 区分严重级别

### 4. Session 级批量同步容错
`syncManager.ts` 实现**幂等重试机制**：
- 同步失败时数据保留在内存中，等待下次触发
- 支持队列式重试（pendingSync 标志位）
- 页面隐藏时自动触发同步，提高成功率

## 关键设计决策

### 无统一错误类型
应用未定义专门的错误类型或错误码，直接使用 JavaScript 原生 Error 对象。这种简单策略适合小型应用，但缺乏结构化错误信息。

### 用户反馈与错误分离
应用将**业务错误**（答题错误）与**系统错误**（网络失败）完全分离：
- 业务错误通过 `FeedbackOverlay` 组件提供鼓励性反馈
- 系统错误对用户透明，仅记录日志

### 儿童友好型错误处理
考虑到目标用户是儿童，应用避免显示技术性错误信息，所有异常都被捕获并转换为友好的用户体验。

## 开发者约定

1. **localStorage 操作**：始终包裹 try-catch，提供合理的默认值
2. **Supabase 调用**：在 API 层抛出错误，不在底层捕获
3. **异步操作**：使用 console.warn 记录非致命错误，console.error 记录严重错误
4. **用户界面**：不向用户展示技术细节，保持界面简洁友好
5. **数据一致性**：依赖本地存储作为单一事实来源，云端作为备份

## 改进建议

当前实现缺少：
- 统一的错误边界组件（React Error Boundary）
- 可观测的错误上报机制
- 结构化的错误分类和重试策略
- 用户可感知的错误恢复提示
