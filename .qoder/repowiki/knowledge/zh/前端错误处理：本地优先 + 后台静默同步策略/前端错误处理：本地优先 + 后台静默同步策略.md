本仓库是一个基于 Vite + React + Supabase 的儿童学习应用，其错误处理体系围绕「本地优先、后台静默同步」设计，核心目标是保证儿童用户交互流畅，网络异常时不中断学习流程。

## 1. 整体策略与架构
- 本地优先（Local-first）：所有学习状态通过 Zustand + zustand/middleware/persist 持久化到 localStorage，页面加载即恢复，无需等待后端。
- 后台异步同步：Supabase 数据拉取在 useAppInit 的 backgroundSync() 中执行，失败仅 console.warn 并回退到本地数据，不阻塞渲染。
- Session 粒度批量同步：syncManager 收集本次会话的变更（宝石记录、错题变动），在学习完成或页面隐藏时统一 Promise.all 并行提交，失败后不清理本地缓存，下次重试。
- 一次性迁移：migrateLocalStorageToSupabase 幂等地将旧 localStorage 数据迁移到云端，失败仅记录日志，不影响后续使用。

## 2. 关键文件与职责
- src/hooks/useAppInit.ts：应用初始化入口，负责后台拉取 Supabase 数据覆盖本地 store，以及一次性迁移。
- src/lib/db/syncManager.ts：集中管理待同步队列，提供 addPendingGem / addPendingError 入队，syncAfterSession 批量提交。
- src/store/useErrorBankStore.ts：错题本 zustand store，记录答错/答对后更新 masteryLevel 和 nextReviewDate，并调用 syncManager.addPendingError 入队。
- src/lib/db/errorBankApi.ts：错题本 API，封装 fetch/upsert，失败直接 throw error 交由上层 try/catch 捕获。
- src/lib/supabase.ts：单例 supabase client，无全局错误拦截。

## 3. 错误传播与捕获模式
- API 层：errorBankApi.ts 中 if (error) throw error，将 Supabase 返回的错误对象向上抛出。
- Hook 层：useAppInit.backgroundSync() 用 try/catch 包裹整个拉取流程，catch 中 console.warn 并忽略，保证 UI 可用。
- 同步层：syncManager.syncAfterSession() 内部 try/catch 包裹 Promise.all(tasks)，失败仅 console.error，不清空 pending 队列，触发递归重试。
- UI 层：音频播放等易失败操作使用 .catch(() => {}) 静默吞掉错误（如 LearnPage.tsx 中的 audio.play().catch(() => {})）。

## 4. 开发者约定
- 新增 API 函数应遵循「失败抛错」模式，由调用方决定是静默降级还是上报。
- 涉及用户可感知的操作不应因网络错误而中断，优先保证本地状态一致性。
- 所有 console 输出需带 [模块名] 前缀以便过滤（如 [Migration]、[SyncManager]、[AppInit]）。
- 不要使用 throw new Error(...) 自定义错误类型，也未发现统一的错误码定义；当前以原生 DOMException/SUPABASE_ERROR 为主。
- 未发现全局错误边界（React Error Boundary）、中间件或 Sentry 等上报集成。
