- **Store 分层**：`src/store/` 下每个业务域一个独立 Store（`useUserStore`、`useLearningStore`、`useMathLearningStore`、`useEnglishLearningStore`、`useGemStore`、`useErrorBankStore`），均通过 `zustand/persist` 以 `rainbow-*` 为 key 写入 localStorage，实现离线可用。
- **类型契约**：`src/types/index.ts` 统一定义 `Question`/`MathQuestion`/`EnglishQuestion`、`DailyProgress`、`ErrorRecord`、`GemRecord` 等接口，所有 Store 与 DB API 共享同一份类型。
- **同步策略**：`src/lib/db/syncManager.ts` 提供单例 `syncManager`，采用「写时入队、闲时批量提交」模式——答题、加宝石、错题库变动只更新本地并记录到 `pendingGemRecords` / `pendingErrorUpdates`，在 session 结束或页面隐藏时通过 `Promise.all` 并行调用 `upsertDailyProgress`、`insertGemRecords`、`updateGemsTotal`、`upsertErrorRecords` 一次性落库；用户信息变更走即时 `syncUserUpdate`。
- **初始化与水合**：`src/hooks/useAppInit.ts` 在应用启动后先让 zustand persist 自动恢复本地数据立即渲染，再后台执行 `migrateLocalStorageToSupabase`（幂等迁移旧 localStorage 至云端）和 `hydrateFromSupabase`（拉取最新数据调用各 Store 的 `hydrate` 覆盖），支持 URL `?reset=YYYY-MM-DD` 一键重置。
- **依赖方向**：Store → `syncManager` → `lib/db/*Api` → `@supabase/supabase-js`；`data/` 下的 JSON 仅作为题目源被 Store 读取，不参与持久化。
